# Lernquest 🎒

Ein Roguelike-Lernspiel für Grundschüler (ca. 3. Klasse) – Monster, Karte, Attacken.
Jede Attacke ist eine Aufgabe: richtig gelöst = Treffer, falsch = der Gegner schlägt zu.
Komplett in einer HTML-Datei, kein Server, kein Account. Deutsch.

**Spielen:** https://thezieger.github.io/rogue-adventures/

## Als App installieren

Lernquest ist eine Web-App (PWA) – einmal installiert, startet es wie eine normale App mit eigenem Symbol und läuft auch **offline**.

| Gerät | So geht's |
|---|---|
| Android (Chrome, Edge, Samsung Internet) | Seite öffnen → Menü ⋮ → „App installieren“ bzw. „Zum Startbildschirm hinzufügen“ |
| iPhone / iPad (Safari) | Seite öffnen → Teilen-Symbol → „Zum Home-Bildschirm“ |
| Windows / macOS / Linux / ChromeOS (Chrome, Edge) | Installieren-Symbol rechts in der Adressleiste oder Menü → „App installieren“ |
| Mac (Safari 17+) | Ablage → „Zum Dock hinzufügen“ |

Updates kommen automatisch: Beim Öffnen holt die App (mit Internet) normalerweise sofort die neueste Version – bei sehr langsamer Verbindung startet nach 3–4 Sekunden die gespeicherte und das Update folgt beim nächsten Mal. Wird ein Update veröffentlicht, während die App offen ist, wird es eingespielt, sobald sie in den Hintergrund geht – nie mitten im Kampf. Ohne Internet startet die zuletzt geladene Version.

- Lesestube: In Deutsch- und Ethik-Einheiten ersetzt sie einen Kampf pro Welt – ein kurzer Text (`src/texte.js`), danach drei Fragen als Angriff.
- Kreisel-Arena: ersetzt einmal pro Welt (Etage 4–6) einen Kampf. Schwung statt Lebenspunkten, erst drei Aufgaben zum Anschwingen, dann Runden in der Schüssel, in der die Kreisel umeinanderkreisen und bei jedem Treffer zusammenkrachen; verlieren kostet nichts. Den Kreisel baut man im Stempelheft unter „Kreisel bauen“ aus Spitze (Wucht), Ring (Panzer) und Scheibe (Schwung) – Teile und Werte in `TOP_PARTS` (`src/logic.js`).
- Duell zu zweit (Titel): zwei Kinder, ein Gerät, abwechselnd Aufgaben aus der eigenen Einheit. Nichts wird gespeichert, auch keine Statistik.
- Kein Zeitdruck. Alle vier Attacken sind von Anfang an da; der Schaden steht als ganze Zahl auf dem Knopf.
- Abwechseln lohnt sich: Dieselbe Attacke direkt nochmal wird „müde“ und macht weniger Schaden. „stark!“ zeigt den Typ-Vorteil.
- Gegenstände: Trank, Großer Trank, Beere, Schild, Chilischote (doppelter Schaden), Eselsbrücke (Tipp), Schutzengel, Fleißbienchen (XP).
- Werkbank (im Stempelheft): Holz (Ereignis „Der Holzplatz“ in Zahlenquest, Siege in der Kartoffel-Werkstatt), Stein und Erz (Bergwerk) und Ernte (Schulgarten) werden nach einer Einmaleins-Sachaufgabe zu Trank, Großem Trank, Schild oder Chilischote (Vorrat, höchstens drei, kommt ins nächste Abenteuer) oder zu Möbeln.
- Meine Hütte (Titel): Zimmer als Bild mit Tisch, Regal (zählt Monsterbuch, Kreiselteile, Notizkarten), Wandhaken, Bett und Fenster; Zweites Zimmer für 30 Stempel und 12 Stein, Dachfenster für einen Sieg durch alle drei Welten von Zahlenquest.
- „Was ist neu?“ im Spiel zeigt `CHANGELOG.md`.
- Jede Aufgabenart hat eine Erklärung („🛈 Wie geht das?“), die beim ersten Mal automatisch erscheint.
- Falsch beantwortete Wissensfragen kommen schneller wieder (Spaced Repetition).
- Elternbereich: Knopf „Eltern“ oben rechts, auf Wunsch mit PIN (beim ersten Start wird sie eingerichtet) in vier Reitern → Üben (Fächer, Spiele, Helden und Aufgabenarten ein- und ausblenden), Fortschritt (Trefferquote, Wochenbericht), Spielstand (Code oder QR-Code sichern, laden, zusammenlegen), App (Töne, Reset).
- Startseite: Klasse → Fach (Kachel) → Thema. Sie baut sich aus `grade` und `subject` der Einheiten selbst auf (siehe „Neue Einheit“).
- „Idee senden“ schickt Ideen, Fehler und Lob direkt aus dem Spiel an ein Google-Formular (kein Konto nötig) – siehe „Feedback“.
- Töne sind gemeinfreie Clips (CC0) in `docs/sounds/` (Quellen in `docs/sounds/SOURCES.md`); Animationen respektieren „Bewegung reduzieren“.
- Fortschritt wird im Browser gespeichert (localStorage), pro Modus ein Spielstand – auch mitten im Kampf. Beim Fortsetzen geht es genau dort weiter. Über den Elternbereich lässt sich alles als Spielstand-Code auf ein anderes Gerät mitnehmen.
- Keine Daten verlassen das Gerät: keine Konten, kein Tracking, keine externen Schriften. Einzige Ausnahme: eine Nachricht, die man selbst mit „Idee senden“ abschickt.
- Bedienbar per Touch, Maus oder Tastatur (Ziffern, ⌫, Enter); hoch- und querformattauglich.

src/musik.js       Musik-Einheit Der Konzertsaal (Fragen, Noten- und Takt-Bilder, Instrumente, Komponisten)
src/monsters.js    Handgezeichnete SVG-Monster (Zeichencode, Quelle für art/)

tools/svg.js       backt die Monster nach art/monsters/raw/ und optimiert nur geänderte mit svgo (Hash in manifest.json)

tests/             Generator-Tests + automatischer Bot-Durchlauf (jsdom)
docs/index.html    gebaute Spieldatei → GitHub Pages
docs/icons/        App-Icons (Android maskable, iOS, Desktop, Favicon)
docs/splash/       iOS/iPadOS-Startbildschirme
docs/screenshots/  Bilder für den Installieren-Dialog (Android/Desktop)
docs/sounds/       Töne (CC0, Quellen in SOURCES.md)

## Entwickeln

```bash
npm install          # nur jsdom für die Tests
npm run build        # Monster-SVGs backen/optimieren (npm run svg) + src/* -> docs/index.html
npm test             # Generatoren, Wissensfragen, Speichern/Laden prüfen (braucht gebautes docs/)
npm run playtest     # Bot spielt alle Modi durch
```

Inhalte anpassen:
- Pflanzenteil-Namen: `PARTS` in `src/knowledge.js`
- Getreide und Wasserkreislauf: `GRAIN_PARTS`, `CYCLE_PARTS` in `src/sachkunde.js`; Auge, Ohr und Fahrrad: `EYE_PARTS`, `EAR_PARTS`, `BIKE_PARTS` in `src/sachkunde2.js`; Orte im eigenen Landkreis: `LANDKREIS` (leer = keine Landkreis-Aufgaben)
- Fragen: `L_POOL` (Luther), `KJ_POOL` (Kirchenjahr, Fragen mit `w: 2` nur in Welt 2), `F_POOL` (Gute Freunde) und `K_POOL` (Kartoffel) in `src/knowledge.js`; Dilemma-Karten in `F_EVENTS`; Ich, wir und die Welt in `src/ethik.js` (`POOL`, Dinge für Drei Welten in `DINGE`, Dilemma-Karten in `EVENTS`)
- Deutsch-Wörter und -Sätze: `src/woerter.js`, Englisch: `src/english.js` (danach `npm run build && npm test`)
- Schwierigkeitsstufen pro Welt: `worldCap` in `MODULES` (`src/logic.js`) bzw. `K_MODULES`
- Gegner/Balance: `ENEMIES` in `src/logic.js`, `L_ENEMIES`/`KJ_ENEMIES`/`F_ENEMIES`/`K_ENEMIES` in `src/knowledge.js`

## Neue Einheit

Jede Einheit trägt Klasse (`grade`) und Fach (`subject`) selbst. Startseite, Klassen-Reiter, Elternbereich, Wochenziele,
Statistik, Spielstand, Tests und der Bot lesen die Einheiten aus einer Liste – es gibt keine zweite Stelle, an der man sie eintragen muss.

**Nur Daten (Fragen, Richtig/Falsch, Lücke, Reihenfolge, Dilemma-Karten):** `src/units/_vorlage.js` kopieren, umbenennen (ohne `_`),
ausfüllen, `npm run build && npm test && npm run playtest`. Die Vorlage erklärt jedes Feld und wird selbst mitgetestet.
Die Tests melden, was fehlt (Erklärung, Elternsatz, Zeichnung, doppelte Namen, Frage ohne richtige Antwort).

**Braucht weiterhin Code:**
- Zeichnungen: jeder neue Held und Gegner in `src/monsters.js`, jedes neue Emoji in `src/icons.js`. Solange darf eine Einheit vorhandene Zeichnungen verwenden.
- Erzeugte Aufgaben (Rechnen, Uhr, Wörter aus Listen) und Bildaufgaben zum Antippen: eigene Datei wie `src/sachkunde3.js` oder `src/jahrmarkt.js`,
  die ihre Einheit in `MK.MODES` einträgt (`gen` bzw. `numGen`) und in `build.py` eingebunden wird. Auch sie braucht nur `grade` und `subject`, um auf der Startseite zu erscheinen.
- Ein neues Fach: eine Zeile in `SUBJECTS` (`src/app.js`).

## Veröffentlichen (GitHub Pages)

Repository → Settings → Pages → Source „Deploy from a branch“, Branch `main`, Ordner `/docs`.
Nach jedem `npm run build` das geänderte `docs/` committen und pushen. Die CI prüft, dass `docs/` zum Stand von `src/` passt.

## Feedback

„💡 Idee senden“ (Startseite und Elternbereich) schickt die Nachricht direkt aus dem Spiel an das Google-Formular „Feedback“ – kein Konto nötig, man verlässt das Spiel nicht. Klappt das Senden nicht (z. B. offline), bleibt der Text stehen und es gibt einen Link, der das Formular mit vorausgefülltem Text in einem neuen Tab öffnet.

Ein anderes Formular verwenden: In `FEEDBACK` (`src/app.js`) die Formular-Adresse (bis vor `/viewform`) und die Feld-ID eintragen. Die Feld-ID findet man über ⋮ → „Vorausgefüllten Link abrufen“ (Teil `entry.123456789` im Link). Das Formular darf keine Anmeldung verlangen und nur eine Pflichtfrage (Absatz) haben.

## Texte und Namen

`tools/unslop-text.md` und `tools/unslop-visual.md` listen die Floskeln und Namensmuster, die im Spiel vermieden werden (Ergebnis einer Analyse von 40 generierten Text- und 20 Spielproben). Neue Gegner, Attacken, Gegenstände, Meldungen und Gestaltung bitte daran prüfen.
